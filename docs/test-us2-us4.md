# วิธีเตรียมและทดสอบ US-2 ถึง US-4

ครอบคลุม AC-2.1–AC-2.6, AC-3.1–AC-3.7 และ AC-4.1–AC-4.5 ตาม `requirements.md` ไม่รวม US-5 งานของฉันหรือ US-6 อีเมลแจ้งงาน

## 1. เตรียมฐานข้อมูลและเปิดเว็บ

1. ต้องทำ US-1 แล้ว: สมัคร/ล็อกอินได้ และมีตาราง profiles ถ้ายังไม่มี ให้ทำตาม `docs/test-us1.md` ก่อน
2. Supabase → SQL Editor → New query คัดลอกเนื้อหาไฟล์ด้านล่างมารัน **ทีละไฟล์ตามลำดับ** แต่ละไฟล์กด Run เพียงครั้งเดียว:
   - `supabase/migrations/20261114060000_us2_teams.sql`: ทีม สมาชิก รหัสเชิญ กฎอ่านข้อมูล และ function สร้าง/เข้าทีม
   - `supabase/migrations/20261114061000_us3_tasks.sql`: งาน สิทธิ์หัวหน้า และข้อบังคับผู้รับต้องอยู่ทีมเดียวกัน
   - `supabase/migrations/20261114062000_us4_task_status.sql`: สิทธิ์เปลี่ยนสถานะและข้อจำกัดคอลัมน์ที่แก้ได้
3. ถ้ารันแล้วแจ้งว่ามีตาราง/function/policy อยู่แล้ว ให้หยุดและส่งเฉพาะข้อความข้อผิดพลาดกลับมา ไม่ลบข้อมูลหรือตารางเดิม และไม่รันไฟล์ US-1 ซ้ำ
4. ไม่ต้องเพิ่มตัวแปรเชื่อมต่อ ใช้ `.env.local` ใน `siriwanhan` ชุดเดิม
5. ใน Terminal ของ `siriwanhan` รัน `npm run dev` (ถ้าเปิดอยู่แล้วใช้ตัวเดิม) → เปิด http://localhost:3000/login

Codex เตรียม SQL แต่ไม่ได้รันกับฐานข้อมูลจริง ตามกติกาใน `AGENTS.md` และสกิล `$supabase-feature` ที่กำหนดให้ผู้ใช้รันเอง

## 2. เตรียมบัญชีทดสอบ

| บัญชี | หน้าที่ | วิธีแยก session |
| --- | --- | --- |
| A | สร้างทีม 1 เป็นหัวหน้า | หน้าต่าง browser ปกติ |
| B | เข้าทีม 1 เป็นสมาชิก | หน้าต่างไม่ระบุตัวตน |
| C | สร้างทีม 2 เป็นคนนอกทีม 1 | browser อีกตัวหรือให้เพื่อนช่วย |

ใช้อีเมลของผู้ทดสอบและรหัสผ่านที่ไม่ใช้กับบัญชีสำคัญ อย่าส่งรหัสผ่าน คีย์ หรือ cookie/token ในแชท หากบัญชีที่ใช้มีทีมแล้วให้ใช้บัญชีใหม่ เพราะรอบนี้ไม่มีฟังก์ชันออกจากทีม

## 3. US-2 สร้างและเข้าร่วมทีม

| AC | สิ่งที่ทำ | ผลที่คาดหวัง |
| --- | --- | --- |
| AC-2.1 | A ที่ยังไม่มีทีมเปิด `/team` | มีฟอร์ม “สร้างทีม” และ “เข้าร่วมทีม” |
| AC-2.5 | กดสร้างทีมโดยชื่อว่างหรือมีแต่ช่องว่าง | “กรุณากรอกชื่อทีม” และไม่สร้างทีม |
| AC-2.2 | A สร้าง “ทีม 1” | เห็นชื่อทีม รหัสเชิญ 6 ตัว และ A เป็นหัวหน้า |
| AC-2.3 | B ลองรหัสผิดก่อน จากนั้นใช้รหัสของ A (ตัวพิมพ์เล็กก็ได้) | รหัสผิดแสดง “ไม่พบทีมจากรหัสนี้”; รหัสถูกเข้าทีม เห็นชื่อ รหัส สมาชิก และบทบาท |
| AC-2.4 | A/B เปิด `/team` หลังมีทีม | ไม่มีฟอร์มสร้าง/เข้าทีม และไม่สามารถอยู่ทีมที่สองได้ |
| AC-2.6 | C ก่อนมีทีมเปิด `/team` และหลังสร้างทีม 2 ตรวจอีกครั้ง | ไม่เห็นชื่อ รหัสเชิญ หรือสมาชิกทีม 1; A/B ไม่เห็นทีม 2 |

สำหรับคำขอพร้อมกัน (AC-2.4) ให้บัญชีใหม่เปิด `/team` สองแท็บ ส่งสร้าง/เข้าทีมในเวลาใกล้กัน ต้องมีสมาชิกเพียงแถวเดียว ไม่มีทีมเปล่า และคำขอที่แพ้แสดง “คุณมีทีมอยู่แล้ว” ฐานข้อมูลใช้การล็อก profile และคีย์ไม่ซ้ำเพื่อบังคับกติกานี้

| AC | สิ่งที่ทำ | ผลที่คาดหวัง |

| AC-3.5 | A เลือกผู้รับแล้วกดสร้างโดยชื่องานว่าง | “กรุณากรอกชื่องาน” และไม่มีงานใหม่ |

| AC-3.2 | A/B เปิด `/tasks` | เห็นงานทีม 1 ในสามคอลัมน์ ชื่อผู้รับ และวันที่รูปแบบไทย |
| AC-3.3 | B เปิด `/tasks` | เห็นงานแต่ไม่เห็นฟอร์มสร้างงาน |
| AC-3.7 | C เปิด `/tasks` ของบัญชีตน | เห็นเฉพาะงานทีม 2 ไม่เห็นงานของ A/B |

ตรวจ AC-3.4 เพิ่มด้วยการเปิด DevTools → Elements ในหน้าของ A แก้ value ของ option ผู้รับงานเป็น UUID ของ C แล้วส่งฟอร์ม ต้องแสดง “ผู้รับงานต้องเป็นสมาชิกในทีมเดียวกัน” และไม่สร้างงาน วิธีนี้ตรวจคำขอที่ข้ามการเลือกปกติ ส่วนชุดทดสอบฐานข้อมูลตรวจการ INSERT ตรงโดยไม่ผ่าน Server Action อีกชั้นหนึ่ง

เปิดจอกว้าง 375px ตรวจชื่อยาว/รายละเอียดและวันที่: กระดานต้องเรียงลงมาและไม่มีเลื่อนแนวนอน ลองตัดเครือข่ายขณะส่งฟอร์มแล้วตรวจข้อความผิดพลาดภาษาไทยและปุ่มระหว่างบันทึก (NFR-3, NFR-4)

## 6. ตรวจสิทธิ์ฐานข้อมูลจริงแบบจำลองบัญชี

การดูข้อมูลใน Supabase Table Editor ใช้สิทธิ์ผู้ดูแล จึงไม่ใช่หลักฐานทดสอบ RLS (กฎจำกัดข้อมูลตามบัญชี) โค้ดนี้ให้ผู้ใช้รันเองใน SQL Editor หลังสร้างทีมและงานแล้ว โดยแทน UUID ของ A, B, C และทีม 1 จาก Dashboard ไม่ต้องใช้ token หรือคีย์

### อ่านข้ามทีม — AC-2.6, AC-3.7

```sql
begin;
select set_config('request.jwt.claim.sub', 'UUID_ของ_C', true);
set local role authenticated;
select * from public.teams where id = 'UUID_ทีม_1';
select * from public.team_members where team_id = 'UUID_ทีม_1';
select * from public.profiles where id in ('UUID_ของ_A', 'UUID_ของ_B');
select * from public.tasks where team_id = 'UUID_ทีม_1';
rollback;
```

ทุก SELECT ต้องไม่คืนแถวใด เปลี่ยนผู้เรียกเป็น B แล้วทดลองอ่านทีม 1 ต้องอ่านได้

### คำขอที่ไม่ผ่านหน้าจอ

รันตัวอย่างต่อไปนี้ **ทีละชุด** และรัน `rollback;` หลังข้อผิดพลาดเสมอ เพื่อไม่ค้างอยู่ในธุรกรรมที่ล้มเหลว ค่า UUID/รหัสเป็นข้อมูลทดสอบ ไม่ใช่คีย์ลับ

```sql
-- AC-2.4: บัญชี B ที่มีทีมอยู่แล้วเรียกเข้าทีมอีกครั้ง
begin;
select set_config('request.jwt.claim.sub', 'UUID_ของ_B', true);
set local role authenticated;
select public.join_team('รหัสทีม_2'); -- ต้องได้ ALREADY_IN_TEAM
rollback;
```

```sql
-- AC-3.3: B สร้างงานโดยตรง ต้องถูกปฏิเสธ
begin;
select set_config('request.jwt.claim.sub', 'UUID_ของ_B', true);
set local role authenticated;
insert into public.tasks(team_id, title, assignee_id, created_by)
values ('UUID_ทีม_1', 'งานทดสอบสิทธิ์', 'UUID_ของ_B', 'UUID_ของ_B');
rollback;
```

```sql
-- AC-3.4: A มอบหมายให้ C โดยตรง ต้องผิด tasks_assignee_in_team
begin;
select set_config('request.jwt.claim.sub', 'UUID_ของ_A', true);
set local role authenticated;
insert into public.tasks(team_id, title, assignee_id, created_by)
values ('UUID_ทีม_1', 'งานทดสอบสิทธิ์', 'UUID_ของ_C', 'UUID_ของ_A');
rollback;
```

```sql
-- AC-4.4: B แก้ชื่อพร้อมสถานะ ต้องได้ ONLY_STATUS_ALLOWED
begin;
select set_config('request.jwt.claim.sub', 'UUID_ของ_B', true);
set local role authenticated;
update public.tasks set title = 'แอบแก้ชื่อ', status = 'done'
where id = 'UUID_งานที่มอบให้_B';
rollback;
```

สำหรับ AC-4.3 เปลี่ยนคำสั่ง UPDATE ให้แก้เฉพาะ status ของงานที่มอบให้ A ต้องคืนจำนวนแถว 0 และงานเดิมไม่เปลี่ยน หากทดสอบผ่าน HTTP API ให้ใช้ publishable key กับ session ของแต่ละบัญชี ไม่ใช้ secret key หรือสิทธิ์ผู้ดูแล และไม่ส่ง token มาในแชท

## 7. ชุดทดสอบในเครื่องและข้อจำกัด

- `npm test`: รวมชุดเดิม US-1, การตรวจฟอร์ม/วันเวลาไทย และ PostgreSQL จำลอง PGlite ในหน่วยความจำ ชุดฐานข้อมูลโหลด migration จริง ใช้ role authenticated/anon และตรวจ RLS, function, FK, trigger โดยไม่อ่าน `.env.local`
- `npm run lint` และ `npm run build`: ตรวจโค้ดและการสร้างเว็บ
- ชุดอัตโนมัติไม่ยืนยันว่า migration ถูกนำไปใช้ใน Supabase จริงแล้ว ไม่จำลองการล็อกคำขอหลาย connection และไม่ได้ยืนยันหน้าจอจาก browser จริง ต้องทำขั้นตอนด้วยบัญชี A/B/C เพิ่ม
- อ่านการเปลี่ยนแปลงใน Source Control แล้ว Commit หลังทดสอบผ่าน ก่อนเริ่ม US-5/US-6
